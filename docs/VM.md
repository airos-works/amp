# Amp's Haiku R1/beta6 test VM

All VM state lives in the ignored `.vm/` folder of this repository. The VM is a clone of
Turbo Chook's beta6 VM and is independent from Kiri's (VNC 5904, SSH 2224), Summit's
(5905/2225) and Turbo Chook's (5906/2226) machines.

| Item | Value |
| --- | --- |
| Guest | Haiku R1~beta6 hrev59866+79, x86_64 |
| VNC | `127.0.0.1:5907` (display `:7`), no password, loopback only |
| SSH | `127.0.0.1:2227`, user `user`, key `.vm/id_ed25519` (`bash tools/haiku.sh`) |
| QMP | `.vm/qmp.sock` (`python3 tools/vm.py status|screenshot|click|drag|type|key`) |
| Disk | `.vm/work.qcow2`, 24 GiB |
| Resources | 6 vCPUs, 6 GiB RAM (`AMP_VM_CPUS`, `AMP_VM_MEMORY`), Intel HDA audio (null backend) |
| Source checkout in the guest | `/boot/home/amp` |
| Test library | `/boot/home/Music/TestMusic` (generated by `tools/make-test-library.py`) |
| Extra packages | `curl_devel`, `sqlite_devel`, `taglib2_devel` |

## Connecting a VNC viewer

Connect to `127.0.0.1:5907` (or display `127.0.0.1:7`). From another computer forward the
port first:

```sh
ssh -N -L 5907:127.0.0.1:5907 your-user@development-host
```

The desktop is 1280 x 800. If the screen saver blanked it, `python3 tools/vm.py key shift`.

## Everyday commands

```sh
bash tools/run-vm.sh                      # start (refuses when already running)
bash tools/haiku.sh 'uname -a'            # run a command in the guest
bash tools/sync-build.sh                  # sync sources and build, printing errors only
bash tools/haiku.sh 'cd /boot/home/amp && make package'
bash tools/haiku.sh 'open /boot/system/apps/Amp'
bash tools/haiku.sh 'hey application/x-vnd.Amp quit'
python3 tools/vm.py screenshot            # PNG in .vm/screen.png
bash tools/haiku.sh 'shutdown -q'         # stop gracefully
```

`AMP_DATA_DIR=/some/folder build-haiku/Amp` keeps settings, library and artwork cache in
that folder. A build under test can run next to the installed Amp (the two are different
files, so single launch does not apply) without touching the library in use.

Haiku's `ps` prints the team name before the id; use `hey <signature> quit` or
`kill $(ps | grep Amp | awk '{print $(NF-3)}')`.

Crash reports: `/boot/home/config/settings/system/debug_server/settings` contains
`default_action report`, so a crashing team writes a report to the Desktop instead of
showing the debugger dialog.

## How it was created

1. Turbo Chook's running beta6 VM was flushed (`sync` in the guest) and cloned live with
   QEMU's `drive-backup` (`tools/clone-disk.py` in the Turbo Chook repository).
2. The clone booted with `tools/run-vm.sh`; a fresh ed25519 key replaced the inherited
   `authorized_keys`; Turbo Chook's checkout, demo repositories and leftovers were deleted.
3. `pkgman install curl_devel sqlite_devel taglib2_devel`.

A first clone made without flushing the guest served corrupted system libraries after its
second boot (parts of `libbe.so` read back as zeros while the package file itself was
intact), so every GUI program failed to load. Verify a new clone with
`md5sum /boot/system/lib/libbe.so` (expected `dafe6d8624e5f0ee04e81ab8fe8b8a9e` for
hrev59866+79) and `package list <haiku hpkg> | wc -l` (6263) before trusting it.
